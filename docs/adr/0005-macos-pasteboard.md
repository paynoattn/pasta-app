# 0005. macOS: pasteboard polling, own-write markers, Universal Clipboard bridge

- Status: Proposed (needs a run of the probe on a Mac + iPhone/iPad)
- Date: 2026-10-23
- Issue: #6 (spike)

## Context

macOS has no public "clipboard changed" notification. Pasta must notice copies cheaply,
skip password-manager items, recognise its own writes, record the source app for the
panel's icon, and (optionally) bridge iCloud Universal Clipboard so iPhone/iPad copies
reach the tailnet and vice versa.

## Proposed decision

- **Watch** by polling `NSPasteboard.generalPasteboard.changeCount` every **250 ms** on a
  background thread with a run loop; read types only when the count changes. This is
  the approach clipboard managers (including Paste.app) use.
- **Read** `public.utf8-plain-text`, `public.html`, `public.rtf`.
- **Skip** items carrying the nspasteboard.org markers `org.nspasteboard.ConcealedType`,
  `org.nspasteboard.TransientType` or `org.nspasteboard.AutoGeneratedType`.
- **Mark own writes** with a custom type `dev.pasta.origin`, **and** keep a short-lived
  set of content hashes Pasta wrote. Don't rely on the marker alone: it may not survive
  Universal Clipboard.
- **Source app** = `NSWorkspace.frontmostApplication` at the moment the change is seen
  (name + bundle id → icon cache in #37).
- **Universal Clipboard items** are expected to carry `com.apple.is-remote-clipboard`;
  label them "iPhone · iCloud" and treat them as local copies to broadcast (#41).

## To confirm on hardware

Run on a Mac:
`cargo run -p pasta-clipboard --example mac_pasteboard_probe -- watch 120`, then
`… -- write 120`, and record:

- [ ] CPU use of 250 ms polling while idle (Activity Monitor), and whether 500 ms feels
      noticeably slower.
- [ ] 1Password / Bitwarden / Keychain Access copies show `concealed=true`.
- [ ] Frontmost app is correct when copying from different apps.
- [ ] A copy on an iPhone/iPad (same Apple ID, Handoff on) appears; does it carry
      `com.apple.is-remote-clipboard`? Latency?
- [ ] `write` mode: does the probe's item reach the iPhone/iPad (i.e. do programmatic
      writes propagate through Universal Clipboard)?
- [ ] After a round trip (Mac → iPhone → copy again on iPhone → Mac), is
      `dev.pasta.origin` still present? (Expected: no → hash dedupe is required.)

## Consequences

- Polling costs a little CPU; 250 ms keeps perceived latency low.
- Universal Clipboard only reaches nearby devices and expires after about 2 minutes;
  Pasta can't change that.
